# RelayLM

[![Проверки](https://github.com/dasferwer/relay-lm/actions/workflows/ci.yml/badge.svg)](https://github.com/dasferwer/relay-lm/actions/workflows/ci.yml)

Единый API для двух LLM-провайдеров с потоковыми ответами, переключением при сбое и учётом расхода. До вызова шлюз резервирует бюджет. После ответа записывает токены и освобождает остаток; после падения процесса восстанавливает учёт из PostgreSQL.

В локальном Compose работают два эмулятора с форматами OpenAI Chat Completions и Anthropic Messages. Они позволяют воспроизвести 429, таймаут, обрыв SSE и отмену клиентом. Реальные адаптеры включены в код, но живые платные API в проверках не вызывались. Цены demo — условные целочисленные кредиты, не доллары и не текущие тарифы провайдеров.

## Запуск

Нужны Docker Compose; Python 3.12 и uv используются для разработки и recovery-проверки.

```bash
make up
make test
make smoke
uv sync --extra dev --frozen
make check
make recovery
```

Swagger: <http://localhost:8180/docs>. Вход через `/auth/login`: `demo@example.com` / `RelayLMDemo123!`. Эмуляторы: <http://localhost:8181/docs> и <http://localhost:8182/docs>.

`make recovery` завершает только API этого проекта через SIGKILL во время потока, возвращает сервис и ждёт истечения 90-секундной аренды запроса. Проверка занимает около полутора минут. База и история сохраняются.

## Правила переключения

| Ситуация | Действие |
|---|---|
| 429, 5xx, таймаут или повреждённый ответ до первого текста | Одна попытка у резервного провайдера |
| 400 или 401 | Ошибка без резервного вызова |
| Обрыв после первого фрагмента текста | SSE `error`, без смешивания ответов моделей |
| Клиент закрыл соединение | Закрыть upstream и завершить учёт |
| Процесс завершён без cleanup | По окончании lease отметить запрос `abandoned`, учесть начатые попытки |
| Повтор успешного `Idempotency-Key` | Вернуть сохранённый ответ без вызова модели |

Circuit breaker общий для процессов API: состояние хранится в PostgreSQL, после паузы допускается один пробный запрос. Отмена пользователем не увеличивает число ошибок провайдера.

Повреждённая структура SSE, неверный тип текста или usage обрабатываются как
ошибка провайдера. Событие проверяется целиком до выдачи текста. До первого
непустого фрагмента доступен fallback; после него поток заканчивается `error`.
Неоконченная попытка учитывается консервативно, резерв освобождается.

## API

`POST /v1/generations` принимает сообщения, `max_tokens` и `stream`. Нужны JWT и `Idempotency-Key`. В потоке идут `start`, `delta`, затем `usage` и `done`; при неуспехе — `error`. Получение HTTP 200 само по себе не означает успешную генерацию.

`GET /usage` показывает бюджет, потраченные и зарезервированные кредиты. `GET /generations/{id}` — отдельные попытки и способ расчёта каждой. Администратор может менять бюджет через `PUT /users/{id}/budget`; уменьшение ниже уже потраченного и удержанного расхода запрещено.

Расход по оборванному потоку оценивается резервом начатой попытки и явно помечается `conservative_reserve`. Это внутренний учёт, не подтверждённый счёт провайдера. Оценка входных токенов не гарантирует верхнюю границу фактического счёта: [подробности](docs/providers.md).
